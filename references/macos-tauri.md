# macOS 菜单栏与 Tauri 壳

## 适用边界

当用户明确只做 macOS、个人自用、需要菜单栏快捷入口时，优先保持一个主看板窗口加一个原生菜单栏 item。不要为了“像悬浮窗”继续堆叠一个容易遮挡、缩放不稳的大浮窗。

推荐的职责分离：

- React/Vite：完整看板、设置表单、计算展示、主题和浏览器预览。
- Tauri/Rust：窗口创建与聚焦、菜单栏标题、菜单动作、退出和必要的 command 边界。
- canonical schedule：同时被 React 和原生菜单栏标题消费。

## 菜单栏设计

- 菜单栏只显示经过格式化的实时金额，例如 `¥459.10`；不要附加无法保证显示完整的长标题。
- 点击左键打开或聚焦主看板；菜单中保留“打开完整看板”和“退出”。
- 如果用户要求透明底或无图标，使用 amount-only title；不要继续挂载蓝色 `¥` 图标或透明图资源。
- 没有原生浮窗时，不要保留无效的 `mini` window、透明窗口配置或不再需要的 macOS 私有 API。

## 工程和权限

- 原生实现要有明确的 macOS-only 声明，不能暗示 Windows 或跨平台行为已经完成。
- 浏览器模式中调用原生 command 应安全 no-op，不能让预览因缺少 Tauri runtime 崩溃。
- 不在代码中硬编码账号、Token、登录态或个人文件路径。
- 原生 UI 的直接验证可能需要 Accessibility 权限；没有权限时报告“已编译/已启动/已打包，但系统菜单栏点击行为未验证”。

## 完成标准

- Tauri 开发编译和 release bundle 成功。
- 主窗口配置、菜单栏标题、打开/聚焦/退出动作与产品范围一致。
- 菜单栏金额与看板金额来自同一派生值。
- 在真实 macOS 中检查标题是否完整、点击是否聚焦、关闭主窗口是否符合预期；没有直接观察证据时保留限制。
