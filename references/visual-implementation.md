# 视觉实现与交互还原

## 视觉事实来源

先查看原图或录屏，记录画布比例、主容器边界、层级、密度、字体、对比度、关键文案和可点击区域。不要因为实现方便而把深色玻璃、蓝色光晕、圆环、图表和按钮变成通用模板。

对于深蓝毛玻璃类界面，优先固定这些关系：

- 深海军蓝背景负责承托，蓝色光线只做层次，不承担文字对比度。
- 主面板使用半透明表面、细边框和有限的 backdrop blur；透明度不足时提供 reduced-transparency fallback。
- 数字、进度环、实时状态和主按钮形成明确的视觉优先级。
- 小入口和完整看板是两个产品表面：小入口只显示最必要的信息，完整看板负责编辑和解释。
- 图表和环形进度必须绑定真实派生数据，不用装饰性动画掩盖数据规则。

## 实现顺序

1. 用固定数据搭建静态页面骨架和响应式断点。
2. 通过真实浏览器检查 1440px 桌面、窄窗口和长中文标签，处理截断、溢出、遮挡和点击区域。
3. 将业务派生值接入 UI；先保持 DOM 结构和视觉 token 稳定。
4. 最后接入 localStorage、Tauri command 或其他外部边界。

## 防止“看似完成”的检查

- 参考图里的窄区域不能被新设置面板挤压到不可读。
- 展开、收起和关闭控件不能被浮层、图表或底部条遮挡。
- 小窗口不能显示不完整的长文案；如果目标是数字入口，就只保留数字和必要单位。
- 不以 DOM 矩形相交直接判定缺陷；要结合截图中的层级、可读性、可见性和实际点击结果。
- 截图工具失败时，明确记录“像素级未验证”，不能用构建成功代替视觉验收。

## 视觉交付证据

至少保留：目标参考、实际渲染尺寸、关键状态截图或替代证据、交互矩阵、已知限制。若采用生成图或模板，记录它只是视觉方向来源，不能当作实现完成证明。
