# 产品验收、打包与发布

## 功能测试矩阵

至少覆盖以下状态：

- 月薪、日薪、时薪三种模式的换算。
- 周一至周日工作日选择，选中日工作、未选日休息。
- 午休开关对计薪分钟、进度、金额和剩余时间的影响。
- 通勤开关以及上班前/下班后分钟数对有效区间和收入的影响。
- 跨零点夜班、当前时间在开始前、工作中、午休中、下班后的状态。
- 非法时间、负数分钟、结束早于开始和午休越界时的校验。
- 保存、刷新、恢复默认值和旧配置兼容。

## 视觉与交互验收

- 桌面主看板：金额、进度、预计收入、距离下班和设置入口都可见且不遮挡。
- macOS 菜单栏：只显示完整金额，点击后聚焦主看板；不出现图标或大悬浮窗。
- iOS 设计：顶部栏尊重 Safe Area，紧凑状态、Widget 和 Live Activity 的信息层级分别成立。
- 检查 1440px 桌面、窄窗口和 iPhone 宽度下的文字截断、间距、点击区域和对比度。
- 页面截图、浏览器交互、macOS 系统 UI 和 iOS 原生运行时是四种不同证据，不能互相替代。

## 构建与测试

按项目实际脚本运行单元测试、类型检查、生产构建、浏览器预览和 Tauri release bundle。测试通过只证明代码路径；原生菜单栏和 iOS Live Activity 仍需在对应系统环境中观察。

## 发布边界

- 发布的 Skill 只包含功能规范、视觉规范、平台边界和必要脚本，不包含 PayDance 源码、用户项目源码、截图、录屏、构建产物、`.env` 或凭据。
- 描述中链接 PayDance 作为功能参考，明确 `shixin` 是独立实现，不冒充原项目。
- GitHub 提交前检查 diff 和远端文件树，只 stage 已确认属于 Skill 的文件。
- 远程推送和仓库创建需要用户授权；认证失败时停止，不索要 Token。
- 发布结果要报告 commit、仓库 URL、通过的测试和未验证的系统级行为。
